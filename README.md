# Safety Detection Backend

Repository: https://github.com/Bibek1604/safety-detection-backend

Deploy this directory as a standalone Render Node Web Service. Leave Root Directory blank.
Use the included render.yaml with New > Blueprint, or configure these settings manually:

- Build: npm ci --omit=dev
- Start: npm start
- Health check: /api/health
- Node: 22

Environment variables:

- NODE_ENV=production
- SERVE_FRONTEND=false (required for the standalone backend)
- SEED_ON_START=true
- MONGO_URI: MongoDB Atlas connection string with a database name and working network access
- JWT_SECRET: random secret of at least 32 characters (generated by the Blueprint)
- ADMIN_EMAIL: administrator email
- ADMIN_PASSWORD: unique password of at least 12 characters
- CORS_ORIGIN: your actual frontend Render origin, such as https://your-frontend.onrender.com, without a trailing slash

Create the backend first. Copy its actual Render URL to the frontend's VITE_API_URL, adding /api. After the frontend is created, update CORS_ORIGIN to its actual URL and redeploy the backend.

Seeding creates both cases and an admin on first startup. Redeploys preserve existing admin passwords and employee attempts. Do not commit .env or node_modules.

Run npm test for configuration, input validation, scoring, retry, seed and HTTP regression checks. Database service tests use doubles; verify the live Atlas connection and game flow after deployment.
